Role isolation holds structurally. Resolver and arbiter stages discard the lease before any launch; arbitration never requests a session; lease creation is gated on `!mission && disposition === 'repair' && primary_round === 1`. Format correction is also correctly excluded: `executeInvocation` for `attemptKind: 'format-correction'` omits `providerSession`, so it returns `providerSessionId: null` and can neither acquire nor extend a lease. Durable state records only provider-neutral facts (`reviewer_continuity`, `reviewer_continuation_lease`) and Attempt `continuity` carries no session identity.

Clarifying scope note for the user gate, not a blocking defect: dropping `--no-session-persistence` means the Claude CLI now retains its own local session transcript for session-aware primary reviews. The contract reserves "retention of full provider transcripts" to the user, but AC-1 requires an *exact reusable* session identity, which is unachievable without provider-side session state; SpecDev itself retains neither the transcript nor the raw session ID as durable evidence. The implementation discloses this in `outcome.md`, `README.md`, and both managed guides.

Three non-blocking observations. (1) `providerSession: { mode: 'capture' }` is requested on every standalone primary round, including rounds ≥2 where `primary_round === 1` makes a lease impossible — this persists provider-local transcripts slightly beyond what continuation needs. (2) The fallback rerun hardcodes `reason: 'resume_failed'` for any non-completion of the continued Attempt, so an unrelated timeout is attributed to resume failure; the retry remains bounded to one. (3) Non-eligible rounds ≥2 record `mode: 'fallback'` with `reason: 'not_immediate_repair_successor'` where `fresh` would read more accurately; the reason field keeps it observable, and continuity field design is delegated authority.
